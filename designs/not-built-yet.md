# Screens the designs have and the product does not

A design export can arrive with a screen nobody has built. That is normal — it is how new work
starts — but it must never be quiet.

Two wrong answers, both of which this file exists to avoid:

- **Let the coverage check go red.** A new screen is not a regression. Failing the build on the day
  it arrives punishes the export rather than the product, and the pressure is then to delete the
  screen from the set.
- **Put it in `superseded.md`.** That file is for references — logo studies, palettes — which are
  design thinking rather than screens anybody signs into. A screen that is real and simply unbuilt
  is not a reference, and filing it as one is exactly the quiet lowering that file warns about.

So: a screen listed here is left out of the percentage **and shouted about on every single run**,
with the date it arrived. The number stays honest and the gap stays visible.

The format is the same as `superseded.md` — `### Screen: <name>` — because a line in a diff is the
whole point.

---

### Screen: SPEC Calls

Arrived **26 September 2026** in Design 20. SPEC answers the business's phone line and makes
follow-up calls.

Why it is not an afternoon's work, said here rather than discovered: **this one needs a layer SPEC
does not have.** The design says so itself — *"Claude is the reasoning layer; Code adds a telephony
+ voice layer (e.g. Twilio with speech-to-text / text-to-speech) — Claude does not answer a phone
line by itself."* A number, a carrier, call forwarding arranged with a phone company, recordings
held for ninety days. None of that is a page, and none of it can be faked convincingly.

What can be built with no carrier at all is most of the thinking: the call list (who takes which
kind of call, prefilled from the org chart), the business facts the owner checks one by one, the
on-call roster it reads at 2am, the two stages, and the rule that a caller in danger is told to ring
000 before anything else. Built first, the day a carrier is connected is a wiring job rather than a
design job.

### Screen: SPEC Function Map

Arrived **26 September 2026** in Design 20. "Capture everything. Then make it simple."

To settle before building: whether it is a MAP of the product or a screen inside it. SPEC Coverage
is the first and is a page; SPEC Colour System is the second and is not. Until somebody has read it
and decided, it belongs here rather than guessed into `superseded.md` — filing a real screen as a
reference is exactly the quiet lowering that file warns about.
